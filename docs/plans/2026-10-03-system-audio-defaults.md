# Temporary system-audio-only desktop release and subtitle defaults

The temporary microphone restriction is superseded by [restored microphone controls and subtitle time](2026-10-05-microphone-subtitle-metadata.md). The other defaults and debugger release boundaries below remain unchanged.

Accepted user request: temporarily hide microphone input, keep the current dev overlay size and font as defaults, then publish a new version.

- Preserve microphone capture, independent lanes, source identity and historical playback/export implementations. Set the native `MICROPHONE_INPUT_AVAILABLE` gate false and expose it as a read-only settings capability. Both dev and production use the same gate; it is unrelated to the development debugger gate.
- Hide input switches and the microphone row in Speech & Translation and the floating control panel; hide microphone subtitle color and remove microphone setup instructions. Keep system-audio status, application/output selection and explicit session start.
- On preference load, normalize a prior microphone/both selection to system audio and clear its recording opt-in, including when a malformed profile catalog blocks catalog edits. Keep existing session files, frame, font and other settings. Public source-selection/save/start IPC rejects unavailable microphone selections before capture. No permission request or automatic microphone fallback is introduced.
- New preferences use font 16. New expanded windows use 659×328 logical units, measured from the user's current dev preferences. Valid saved user geometry/fonts continue to win; position still adapts to the display work area. Native and frontend invalid-font fallback agree.
- The debugger is excluded at build time from formal releases: the default-off `development-debugger` Cargo feature contains commands, private content/audio capture and the trace journal; production adapters only pass through network futures. The dev launcher explicitly enables it, with the existing dev runtime and exact `app.yuxino.mimi.dev` identifier still required. Frontend production builds exclude the debugger and event observation code. Production creates no evidence directory, reads no evidence workspace and exposes no debugger IPC. Release verification rejects debugger command/storage markers in the executable. Historical microphone recordings keep their labels and remain readable.

Verification: focused UI tests exercise unavailable/missing capabilities, retain dual-input coverage with explicit future-availability fixtures, and verify system app selection remains. Rust tests cover rejecting microphone/both and normalizing persisted selections without losing existing display preferences or retaining old-source recording opt-in. Run the full repository check and signed canonical dev UI acceptance before release.

Acceptance: canonical `scripts/check.sh` passed (1045 Rust tests, 1075 frontend tests, 37 evidence-analyzer tests and 9 batch-scheduler tests). Signed canonical dev UI-only inspection confirmed font 16, hidden microphone/input switches and microphone color controls, and retained system application selection in settings and the overlay control. The normal local-dev session was restored with its existing preferences and selected application. Temporary UI fixtures require the actual OS `TMPDIR` subtree; `/private/tmp` is not necessarily accepted on macOS.

The first executable scan rejected residual debugger command names in the generated Tauri ACL manifest, even though their implementations were compiled out. The build script now derives its application permissions from the checked-in template, excluding those commands unless the development feature is explicitly enabled; ordinary window and session permissions remain. The artifact scan stays strict and is rerun on the rebuilt signed packages.
