# 配置选择的可用状态与原因

## 问题与决定

设置的服务列表会显示缺失凭据并禁用“使用”，但字幕控制面板将全部保存
配置直接作为可选项；声音设置虽会禁用，也没有显示原因。空闲时后端允许
仅切换配置元数据，因此前端遗漏可能真的选中尚未配置的服务。

按用户选择，保留不可用项、禁用切换并显示简短原因。隐藏会让已保存配置
看起来消失，只有灰色又不足以说明如何恢复。配置完成后随现有快照恢复可选，
当前项失效时保留身份与说明，不自动切换、删除或修改配置。

## 最小实现

- 浮窗（内嵌及独立面板）和声音设置复用一个基于现有非敏感快照的判断。
  复用 `Select` 已有的禁用项和描述，不增加设置、探测请求或状态系统。
- 禁用项只淡化名称、图标与勾选标记；原因保留普通描述的可读性，避免
  行透明度与描述透明度叠加后过淡。菜单尺寸与交互不变。
- 使用配置的语言预设目标，缺省才使用当前目标。Apple／自定义识别的
  原文模式只要求识别槽；已有合法无密钥配置不因未保存可选密钥被禁用。
- Alibaba 实时模式另须 workspace。缺失配置与读取不可用保留不同原因；
  正常项维持简洁，已有语言预设说明不丢失。
- 设置服务列表、编辑和新增入口仍可达；Apple 的资源准备与“下载并使用”
  具有独立准备语义，不套用普通配置切换限制。原生托盘没有配置选择菜单。
- 后端运行／暂停切换前的完整配置校验，以及空闲元数据选择的免凭据读取
  规则保持不变。不按名称去重不同配置 ID。

## 验证范围

固定样本覆盖缺失／不可用凭据、缺 workspace、原文模式、语言预设、同名
配置、当前项失效、恢复和正常切换；鼠标及键盘都不能提交禁用项。检查实际
React 菜单的多语言、窄宽度和明暗主题。用户仍在使用正式应用，后台浏览器
样本与自动测试不能记为 macOS 原生交互、真实凭据或设备验收。
