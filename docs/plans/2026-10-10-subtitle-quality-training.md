# 现有服务的字幕质量训练

## 目标

继续改善 Mimi 使用现有识别和翻译服务的实际效果：少漏句、少错义，
字幕及时出现，更新和断句便于阅读。每轮用相同输入证明改善，保留失败样本。
本轮先暂停本地模型方向；这里的训练沿用项目的样本验证和回归修复流程。

## 第一轮范围

先核对 [既有质量记录](../development/integration-runs.md) 中的固定样本与
私有归档。首轮候选是日语长句和英语专名句，翻译目标为中文，附音乐和
数字静音对照。旧 reference 未独立听审，先校订参考，再判断模型错误。
样本不可用时记录缺口；新增输入另给身份，不能冒充原失败样本的复测。

先选一个现有服务和一套模型配置，固定语言、音频、输入处理与运行设备。
通过后再扩展语言或服务，不同时调多个变量。每轮只解决最早有证据的
一个失败边界，复测原样本及容易受影响的相邻场景。

归档重开后，先聚焦英语专名：旧日语长句的四处字符差异只是同一词的
汉字／假名写法；英语六处词差异中有两处等值数字写法，余下涉及三个
人名。专名的听审参考尚未确认，不把这些差异直接定性为模型错误。
四例准备矩阵保留旧模型、`auto` 和 `bypass`，不同时改识别语言或提示词。

| 目标 | 本轮证据 | 通过条件 |
| --- | --- | --- |
| 更准确 | 听审原文、ASR 差异、译文语义单元；单独检查专名、数字、否定、条件和指代 | 原失败确实改善，新增重大增义或漏义为零；未知参考不评分 |
| 更及时 | 语音时段、首个草稿、确认原文、确认译文和原生显示的独立时间点 | 使用相同计时边界报告前后延迟，不能用连接 RTT 或请求耗时代替字幕延迟 |
| 更舒服 | 草稿修订与回退、断句、完整行可见性、长句和连续播放的原生观察 | 已确认内容稳定，最新字幕可读；模型修订不被误判成应当冻结的最终文字 |

每次修复先写明预期改善的指标与允许范围，再执行前后对比。延迟、准确度
和阅读体验互为约束，不能只追一个总分，也不预设所有语言的统一阈值。

## 执行入口

复用 [音频质量基线重放](../development/audio-quality-replay.md) 的操作入口，
现有 `run-development-batch.py` 负责准备和有界服务测试，
`analyze-development-case.py` 负责离线分层分析。不新增评测框架。

1. 重开原归档，核对输入、reference 版本、hash、来源和对应 request/events。
2. 不带 `--run` 准备本轮矩阵，区分语音例、音乐与数字静音，检查 PCM/WAV 一致。
3. 按本轮实际服务范围建立基线。系统音频原生播放串行；开发取证显式开启，
   记录 revision、配置与实际执行区间。服务请求、听审、原生显示分别记录。
4. 对照服务输出、后端接纳、共享状态和实际字幕窗口，定位最早偏差。
5. 有确定缺陷才修产品：便携行为放在共享 Rust，原生显示问题留在平台适配层。
   补充对应边界回归，保持上游协议和提示词契约。
6. 重跑原失败样本及必要相邻检查，记录改善、退化和仍未知项；再决定下一轮。

语义参考、音频、字幕和完整请求留在 Git 外。公开记录只保留样本身份、
计时边界、计数、受测 revision 与结论。当前默认关闭的历史和录音选项
按既有规则保持独立；本轮取证不改变正式版配置。

## PR 完成条件

这是一个持续工作的草稿 PR。准备矩阵和自动回归通过只是开工条件，
不能宣称字幕质量提升。完成一轮后，PR 必须能展示：

- 一个具体问题、固定输入与可比基线。
- 最早失败边界及对应最小修复；未复现则保留有依据的无改动结论。
- 同样本复测、原生阅读观察、必要自动检查及未验证平台的范围。
- [实测记录](../development/integration-runs.md) 中可继续复用的下一项检查。

满足以上条件后才结束本轮；本草稿暂不合并或发布。
