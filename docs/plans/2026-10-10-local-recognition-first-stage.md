# 本地识别首版：目标与研究范围

状态：研究草稿。产品目标已确认；模型、运行时、首批平台和性能门槛待讨论。
本 PR 只形成研究边界，不提供模型功能或发布承诺。

## 产品目标

普通用户不用申请识别 API Key、不用安装 Python 或自行启动服务器，
在 Mimi 里下载一个模型，就能把电脑播放的声音稳定转成实时字幕。
模型下载完成后，识别可离线运行。文字翻译继续使用现有的独立配置；
界面需明确哪些步骤在本地、哪些会联网。

用户流程保持简单：选择模型 → 下载 → 启用 → 开始字幕。
下载入口应显示大小、进度、取消和重试；已下载模型可启用或确认删除。
启动应用、检查连接和开始字幕不暗中下载模型。

## 首版边界

- 先选一款识别模型和一种运行时，把完整字幕链路做稳，再扩充模型目录。
- 长期需要桌面跨平台；首个实际验收平台、参考设备及后续平台顺序单独确定。
  不把一台机器的成功描述为所有平台已支持。
- 复用现有系统音频采集、字幕状态和独立文字翻译，保持麦克风显式选择、
  历史和录音默认关闭。模型可用不等于新的采集能力已经可用。
- 支持连续使用、暂停、恢复、清空和停止；队列与文本有界，旧会话结果不能
  进入新会话，停止后释放运行资源。
- 只管理 Mimi 自己下载的模型；外部运行时的模型不能按 Mimi 私有文件处理。

本地文字翻译、多运行时自动选择、通用自定义程序编辑器和更多模型，
分别讨论后续阶段，不随首个本地识别实现一起扩张。

## Windows 用户是否需要 Mimi

依据 [Microsoft Live Captions 官方说明](https://support.microsoft.com/en-us/accessibility/windows/use-live-captions-to-better-understand-audio)，
Windows 11 22H2 及以上已提供独立可用的本地字幕，首次需要下载语言文件。
LC 支持离线处理、可移动浮窗及字幕样式；Copilot+ PC 在 Windows 11 24H2
及以上还能将支持的来源语言翻译成英文或简体中文。文档明确字幕不会保存。

研究建议：如果 LC 已满足用户的字幕需求，用户直接使用 LC 即可。
浮窗和本地识别本身不能当成必须接入 Mimi 的理由。

| 目标场景 | 对 Mimi 的判断 |
| --- | --- |
| 普通 Windows 11，看支持语言的原文字幕 | 直接使用 LC 即可 |
| 满足系统及硬件条件，所需英/简中翻译在 LC 支持范围内 | 先直接使用 LC，确认实际效果是否足够 |
| 普通 PC 需要翻译、需要其他译入语言或按需保存字幕 | 存在值得研究的缺口，再比较 Mimi 能增加的价值 |

上述缺口不自动意味着要接入 LC。直接运行识别模型和读取 LC 字幕窗口是
不同技术路线，须比较体验、质量和维护成本；复用 LC 也不会自动提高其
识别质量。当前研究不决定恢复以前的 Windows 接入实现。

## Ollama 是否可以复用

`ollama pull <model>` 是下载模型；`ollama run <model>` 是运行模型。
Ollama 也提供模型下载 API，因此可以研究由 Mimi 提供按钮的方式。
这些能力本身不证明候选语音模型能够在指定 Ollama 版本上运行，
也不证明短音频请求适合连续实时字幕。

当前找到社区维护的 `frozenlab/qwen3-asr` 包。它的说明要求运行时具有
`qwen3a` 音频投影支持，通过 chat 请求的 `images` 字段传入音频。
这只是包装作者的使用说明，不是 Mimi 实测，也不能当成官方兼容承诺。
是否支持普通用户安装的正式 Ollama 版本、分块时延和生命周期，需要核对。

| 路线 | 对用户的影响 | 研究重点 |
| --- | --- | --- |
| Mimi 内置单一识别运行时 | 下载后直接使用；无需另装服务 | 模型质量、资源占用、各平台打包及停止时释放资源 |
| 接入本机 Ollama | 复用外部模型管理；需要可用的 Ollama 安装与服务 | 正式版本的音频支持、模型兼容、实际延迟、安装与故障处理成本 |
| 要求用户配置任意程序或服务器 | 灵活，但增加设置步骤 | 适合作为已有高级接入方式，不作为默认首版流程 |

先比较前两条路线，依据同一输入和目标设备的结果选择。
如果外部运行时显著简化实现，再讨论是否接受安装外部应用作为首版前置条件；
目前不默认新增这项要求，也不预先排除 Ollama。

参考：[Ollama CLI](https://docs.ollama.com/cli)、
[模型下载 API](https://github.com/ollama/ollama/blob/main/docs/api.md#pull-a-model)、
[社区 Qwen3-ASR 包](https://ollama.com/frozenlab/qwen3-asr)。

## 旧 PR 的处理

[#225](https://github.com/yuxino/Mimi/pull/225) 同时包含模型管理、MLX 与 ONNX
运行时、多模型、自定义程序和跨平台构建。已有代码与实测可供复用，
但首版按本目标挑选必要部分，并重新对照当前共享运行时边界。

旧 PR 的 Linux worker 短音频推理和早期 Mac MLX 实测，分别只证明各自的
受测组合。新 ONNX worker 的 Mac/Windows 原生字幕、持续使用和背景音乐
表现仍待验证；不能把不同组合的结果拼成完整首版验收。

可移植的识别接入、调度和字幕业务继续由 `shared/mimi-runtime` 与
`shared/mimi-core` 承担。原生进程启动、打包和平台能力留在适配层；
不把旧分支的桌面业务实现原样复制回来，也不另写 Android 业务副本。

## 研究与验收顺序

1. 确定首个验收平台、参考硬件、主要语言和内容场景；先验证系统字幕能否
   已满足该场景，围绕仍存在的用户需求确定 Mimi 的首版价值。
2. 以官方资料核对最多两款候选识别模型及运行时的许可、格式和平台支持。
   先比较真实识别效果与速度，再决定首版的一款模型。
3. 使用可合法测试的固定片段，在相同条件下比较清晰讲话、连续长句、
   短暂停顿和背景音乐。记录精确版本、冷启动、内存、推理与音频到字幕的
   时间，区分 worker 速度和完整字幕时延。
4. 定义可测的首版门槛，再做最小端到端原型。验证持续播放不累积延迟、
   原文不遗漏或重复、暂停/清空/停止正确，以及下载失败和取消后的恢复。
5. 在同一候选包上完成真实系统音频和持续会话验收，再讨论进入 main。

遵循现有集成学习流程。已有音频和凭据保持私有；本研究 PR 不开始新采集、
模型下载或真实服务调用。实验授权和成本按实际实验另行确定。

后续实现 PR 每次交付一个可验证结果；模型、运行时或平台增加时先重新确认
是否属于当前里程碑。测试通过和包能生成，分别不能代替实时字幕验收。
