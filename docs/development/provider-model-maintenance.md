# 供应商与翻译模型维护

目标是让 Mimi 持续用上**在真实字幕场景中翻译更好的模型**。新版、旗舰、
官方榜单成绩和接口仍可连接，都不能单独证明值得升级。质量收益需要在
可接受的延迟、费用和稳定性范围内成立。

## 何时检查、谁来收尾

- 每次发布准备检查官方更新、弃用通知和未完成的升级候选；距完整巡检
  超过 30 天时补做完整巡检。开发长期暂停后，在下一次相关工作开始时补查。
- 新接入或修改供应商、收到翻译退化反馈、发现新翻译模型、预览模型到期
  或别名指向变化时，立即做该路线的定向检查，不等下一次完整巡检。
- 完整巡检覆盖当前 factory 的内置路线和共享服务预设；用户自填模型、私有
  部署及本地模型只核对当次涉及的配置，其余注明未覆盖，不枚举用户私有设置。
- 当前任务的协调者负责更新[巡检记录](provider-model-reviews.md)，把每项
  发现落成明确的下一步、复查日期或已验证结论。相同日期且来源未变的检查
  可以复用；不能把未查项目标成通过。
- 本页规定人工维护流程，不建立后台定时任务。网络请求、付费评测、
  原生播放、捕获和发布继续遵守当次授权及
  [集成学习流程](integration-learning-loop.md)。

## 先查实际路线，再查上游

以共享实现为准，区分识别、文字翻译和一体式语音翻译：

| 核对项 | 拥有这项事实的位置 |
| --- | --- |
| 实际路由、独立翻译与生效模型 | [共享配置](../../shared/mimi-runtime/src/core/configuration.rs)及调用它的 provider factory |
| 内置模型、请求参数、流式及结束事件 | [共享协议](../../shared/mimi-runtime/src/core/protocols/)与 clients |
| 新配置的示例模型、服务入口、必要限制 | [共享服务文案](../../shared/provider-copy.json) |
| 语言、模型差异及桌面／Android 行为 | [语言目录](../../shared/provider-language-catalogs.json)、[平台差异](platform-parity.md)、[共享契约](../../shared/translation-contracts.json) |

记录模型完整 ID、固定版本或滚动别名、API 版本、区域和生效配置。
预设只是新配置的编辑草稿，不能据此推断用户已保存配置正在使用该模型。
Azure 部署名、本地模型和自定义服务还要区分部署名称与实际模型版本；
无法确认服务端版本时明确记为未知，不读取或公开用户密钥。

从官方模型目录、API 文档、更新／弃用公告与价格页核对：

- 当前模型是否可新建、仍受支持、已弃用或已给出下线日期，推荐迁移到什么；
  官方页面可见不等于该区域、账户和额度实际可用。
- 是否有更适合字幕翻译的候选；同时看语言对、术语／上下文能力、流式返回
  与最终结果规则、思考开关等参数兼容性、限流、计费和认证要求。通用聊天模型
  也需验证仅输出译文。
- 别名、服务默认值或托管模型是否在代码未改时发生变化。能固定版本时记录
  选择理由；只能使用服务默认时记录不可固定的限制，并复测代表样本。
- 链接、核对日期、官方公布的生效／下线日期分别保存。搜索摘要和第三方
  排名只用于找线索；官方来源冲突或打不开时记录未知，不猜模型 ID 或替代品。

每项使用“已核对文档”“待实测”“已验证可升级”“保留当前”“待迁移”
或“未知”，写清对应证据。无弃用公告只表示本轮未找到，不能承诺永久支持。
识别模型升级单独评估；不能用识别变准来冒充文字翻译模型本身变好。

## 用相同样本比较翻译质量

沿用[样本库和复测流程](integration-learning-loop.md#从短样本走向可重复的场景库)，
先写本轮语言对、目标问题、费用／请求上限、通过标准与停止条件，再调用服务。

1. 先固定同一份识别结果比较新旧文字翻译，保持分句、上下文、提示词及可比
   请求参数一致，只改变待评估项。一体式服务无法拆分时明确这个限制，
   使用相同音频与发送节奏比较整条路线。
2. 使用来源明确的代表样本和原失败样本，覆盖当前目标语言中的对白接续、
   人名术语、数字、否定和省略等实际难点。阅读原文与译文，核对漏译、误译、
   幻觉、术语一致性及自然度；可匿名对照，关键争议由理解该语言的人复核。
   必要时重复同一批输入区分随机波动；单一自动分数或另一模型评分不能独立决定升级。
3. 分别记录首个可读译文、最终译文及端到端可见字幕的计时边界；检查流式
   改写、最终配对、长句、取消与停止收尾。样本足够时报告 p50/p95，
   样本不足时报告实际范围和数量，不制造精确统计结论。
4. 按实际 token／字符／音频计费口径比较费用，包括草稿、重试与最终翻译；
   写清价格日期、区域和币种。不能仅比较单次请求或厂商标价。
5. 完成适用的文本或同音频路线对照后，用签名开发应用及同一音频完成相关真实链路复测。
   保留旧结果与未验证场景；模拟服务和 JNI 契约不能代替服务质量验证。

私有音频、识别文本、译文、reference 与凭据留在 Git 外；仓库只记录
样本 ID／哈希、配置、计时、计数、匿名问题分类和结论。评测正文不进入普通日志。

## 决策、交付与回退

- 主动质量升级需有翻译改善证据，延迟、费用和稳定性在预先约定范围内，
  才把候选列为推荐或修改新配置默认值。保留当前模型也应写明原因与复查条件。
- 质量更好但代价明显增加时，提供明确取舍供用户选择，不直接更换所有路线。
  弃用迁移按可用性、可接受的质量底线、延迟和费用另行验收，与主动质量升级
  分开记录；被迫迁移也不能宣称翻译质量已提升。
- 保存的服务、模型、区域和独立翻译选择不静默改写。模型退出服务时给出明确
  原因和迁移路径，不暗中降级到其他模型或供应商；停止会话后再切换。
- 共享模型／协议变更进入 shared runtime，更新真实行为契约并运行直接 Rust、
  实际 JNI、所需桌面／Android CI 和相关原生验证。文案由共享文件生成，
  九种语言保持等价；能力差异更新对应目录及平台说明，不重写官方协议提示词。
- 升级前记录可用的旧模型／配置及回退办法，验证旧配置加载与用户主动回退。
  旧模型已下线或滚动别名无法固定时明确回退限制，不能承诺一键恢复旧输出。
- [巡检记录](provider-model-reviews.md)保留来源、候选状态与下一步；
  [实测记录](integration-runs.md)保留准确 revision、样本、构建与验收边界。
  发布说明只陈述用户可见的已验证变化和必要迁移操作。

纯巡检与 SOP 修改只检查差异、链接和格式；不为文档构建应用。
