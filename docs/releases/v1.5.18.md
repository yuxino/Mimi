## English

- Android and desktop now run the same Rust provider clients, translation scheduling, subtitle rules and recovery policy. Provider fixes reach both platforms through the shared runtime and Android JNI bridge.
- New sentence previews no longer keep the preceding completed sentence on screen. Android compact captions follow the latest lines of long continuous translations. Immersive toggles preserve the floating window's position and expanded reading state; growing history keeps the current caption visible when you are following it.
- Android shows the active model on Home and expanded subtitles, blocks model edits until Stop, and displays shared connection, retry and timeout feedback.
- Gemini Stop now preserves a paired final subtitle when its continuous stream omits `turnComplete`; the same repair applies to desktop and Android.
- Diagnostics moves to Advanced in desktop General settings and Android Settings, leaving common subtitle actions together.
- Windows build checks now handle UTF-8 source, repository paths and LF/CRLF license inventories consistently.

Validation: shared Rust and actual JNI regressions, strict desktop/frontend checks and both Android build variants passed locally. API 35 native checks cover dragging, immersive restoration, landscape geometry, narrow large-font layouts and seven interface languages. Bilibili playback produced source, translation and final subtitles with Alibaba Lite/Flash/Plus, Gemini, Volcano, Tencent and Baidu, including normal Stop and restart checks. PC Gemini confirmed the repaired final-pair publication; the Alibaba comparison observed 429 backoff followed by a completed final translation. OpenAI live acceptance was blocked by the saved account's exhausted credit balance. These are short emulator/development checks; physical devices, sustained sessions, semantic accuracy and cross-platform end-to-end latency remain unaccepted. [Implementation and acceptance evidence](https://github.com/yuxino/Mimi/pull/229).

Desktop updates are available in Settings → General. Portable ZIP and `.deb` packages require manual installation; Android users install the new APK over the existing app. Some Android playback apps block audio capture. macOS keeps its fixed signing identity and is not Apple-notarized. Intel Mac runtime, installed updater transitions and the existing Baidu silence-session limitation remain unverified or unresolved.

## 中文

- Android 与桌面端统一使用 Rust 实现的服务客户端、翻译调度、字幕规则和恢复策略。服务修复通过共享运行时和 Android JNI 桥接同时应用到两端。
- 新句预览不再一直停留在上一句已完成字幕。Android 紧凑字幕会跟随长段连续翻译的最新文字；切换沉浸模式时保留浮窗位置与展开阅读状态；跟随当前字幕时，历史增长不会再把当前字幕挤出视野。
- Android 首页和展开字幕显示当前模型；运行时需先停止再编辑模型，并显示共享的连接、重试和超时状态。
- 修复 Gemini 连续翻译未返回 `turnComplete` 时，停止操作可能丢失最后一段成对字幕的问题，同时应用于桌面与 Android。
- 诊断移到桌面端通用设置和 Android 设置的高级区域，常用字幕操作保持集中。
- 修复 Windows 构建检查对 UTF-8 源码、仓库路径及 LF／CRLF 许可证清单的兼容问题。

验证：共享 Rust、真实 JNI 回归、桌面与前端严格检查及 Android 两种构建均已在本地通过。API 35 原生检查覆盖拖动、沉浸恢复、横屏尺寸布局、窄屏大字号和七种界面语言。B 站实播中，阿里 Lite／Flash／Plus、Gemini、火山、腾讯和百度均产生原文、译文和最终字幕，并检查了正常停止与重新启动。PC Gemini 对照确认修复后的最终字幕发布；阿里对照观察到 429 退避后最终译文完成。OpenAI 实播因已保存账号余额耗尽而受阻。这些是短时模拟器／开发构建检查，未代替真机、长会话、语义准确率和跨平台端到端延时验收。[实现与验收证据](https://github.com/yuxino/Mimi/pull/229)。

桌面端可在设置 → 通用中更新；绿色 ZIP 与 `.deb` 包需手动安装，Android 用户使用新 APK 覆盖安装。部分 Android 播放应用会禁止声音采集。macOS 保持固定签名身份，未经过 Apple 公证。Intel Mac 运行、已安装版本的更新过程及既有百度静音阶段会话限制仍未验证或解决。
